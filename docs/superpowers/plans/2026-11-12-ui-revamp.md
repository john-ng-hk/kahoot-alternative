# UI Revamp Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Restyle every in-scope screen (host dashboard, how-to, host lobby/quiz/results, player lobby/quiz/result) with one shared visual system, without changing game behaviour.

**Architecture:** Add colour and component tokens to Tailwind (`tailwind.config.ts`, `src/app/globals.css`), plus two shared components (`Button`, `Notice`). Then restyle each screen file in place, one task per screen. Replace every `alert()` on in-scope screens with an inline `Notice`.

**Tech Stack:** Next.js 14 App Router, React 18, Tailwind 3, Inter font, `react-countdown-circle-timer`, `react-confetti`, `next-qrcode`.

**Spec:** [docs/superpowers/specs/2026-11-12-ui-revamp-design.md](../specs/2026-11-12-ui-revamp-design.md)

## Global Constraints

- Do not run `git commit` or `git push`. The user's CLAUDE.md forbids it without an explicit request. The skill's "frequent commits" step is replaced by a final `git status` check (Task 11).
- Do not add a test framework. The spec does not ask for one, and the project has none. Each task is verified with `npm run lint`, `npm run build` and the manual checks listed in that task.
- Do not change game logic, the `games.phase` state machine, realtime subscriptions, `src/constants.ts`, `src/types/*`, migrations, or seed data.
- No IMHK or Ingram Micro colours or branding.
- Text contrast at least 4.5:1 for body text and 3:1 for large bold text (WCAG AA). Check each colour pair listed in Task 1 with a contrast checker.
- Tap targets at least 44 px tall (`min-h-[44px]`).
- Player screens must work at 375 px width. Host screens are sized for a projector and checked on a laptop.
- Minimal diff: change only the classes, markup and alert replacements the task names. No unrelated refactors or renames.
- Run `npm run lint` and `npm run build` at the end of every task. Both must pass with no new errors.

## Review Focus

Input classes the spec implies but no test covers. Each line names the task that owns the code and the check that pins it.

1. Long nicknames (max 20 characters) and long question text wrap without overflow at 375 px and on the host projector layout → Task 6 (host question), Task 8 (nickname on player lobby), Task 9 (question text on phone).
2. Quizzes with 2 or 3 choices lay out and stay tappable on player and host screens → Task 6 (host bars), Task 9 (player buttons).
3. 30 or more players in the host lobby: the list scrolls and the Start Game button stays visible → Task 5.
4. A quiz set with zero questions: dashboard disables Start Game and does not crash → Task 3.
5. Tied scores in results, including several players with 0: tied players share a rank → Task 7.

|---|---|

| `ink` on `answer-yellow` `#fbbf24` | about 11:1 |
| white on `answer-green` `#15803d` | about 5.0:1 |
